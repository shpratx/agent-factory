🔍 Quality Assurance Layer
A12: Quality Verifier Agent
Independent rubric-based scoring
Used after: vision, requirements, epics, stories, HLD, code (API + UI)
18 quality gates across full lifecycle (min score 7/10, except task-completeness ≥6)
Patterns active: Reflection (all agents) · Verification (critical steps) · CoT (design + planning agents) · Grounding (all agents) · Citation (vision, story, test agents) · Graph reasoning (dependency mapper)
🛡 Guardrail Chain (applied to every agent output)
1. gr-L1-output-schema-validator
Reject if output doesn't match JSON schema
2. gr-L1-pii-detection
Block if real PII found in output or synthetic data
3. gr-L1-hallucination-check
Flag ungrounded claims (entities, references)
4. gr-L1-consistency-check
Flag contradictions within/across phase outputs
5. gr-L2-food-domain-compliance
Validate HACCP/Natasha's-Law references correct
6. gr-L1-secret-scanner NEW
Block hardcoded credentials in generated code
7. gr-L1-license-compliance-check NEW
Flag disallowed OSS license in generated dependencies
📊 Observability & Audit
Correlation ID: Generated at Idea intake; propagated through all 8 phases, every agent, tool, and event
Events: workflow.started → phase.*.started → step.*.completed → step.*.quality_gate.pass/fail → phase.*.completed → workflow.completed
Audit trail: Input, output, reasoning (CoT), citations, quality scores, guardrail results per step, per phase
Version manifest: Agent versions, instruction hashes, KB versions, model, tokens, cost
HITL logging: If quality gate fails → Jira subtask created, human decision recorded; 4 explicit human gates (Vision, Roadmap, Design, Code review) per 00-ai-augmented-sdlc.html
🧬 Layering (per naming standard)

Every agent below is defined at L1 (Enterprise) — generic, reusable across any domain. For a specific LOB, extend via instructions_append + knowledge_bases_append, e.g. L2-food-domain-vision-market-analyzer extends L1-vision-market-analyzer with HACCP/Natasha's-Law framing. For a specific project, L3-{project}-design-hld extends the L2 domain agent with ADRs and sprint baselines. Tools remain L1 unless the system is domain-specific (e.g. tool-L2-food-domain-cold-chain-sensor-read). See 01-agent-development-naming-standard.html for the full inheritance model.
