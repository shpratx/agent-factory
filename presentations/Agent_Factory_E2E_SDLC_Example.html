End-to-End SDLC Example — Ideal Agent Architecture

From Requirements to PR: A Complete Reference Implementation

The Use Case

Input: A business initiative — "Add domestic fund transfer capability to mobile banking"

Output: Jira epics/stories/tasks + UX wireframes + API specs + HLD/LLD + generated code + test cases + GitHub PR

Flow:

Initiative → Epics → Features → Stories → UX Design → API Design → HLD/LLD → Code → Tests → PR

Agent Spec Example — A3: Story Generator

spec_version: "1.0"
artifact_type: agent
metadata:
  name: L1-inception-story-generator-agent
  version: "1.2.0"
  layer: L1
  phase: inception
  owner: ai-tech-lab

purpose:
  description: "Generates user stories with acceptance criteria from a feature description"
  business_value: "Reduces story creation from ~2 hours to ~8 minutes per feature"

behavior:
  model: claude-sonnet-4.5
  temperature: 0.2
  max_tokens: 4096
  
  instructions: |
    You are a senior business analyst. Given a feature description and context from
    the knowledge base, generate user stories.
    
    FORMAT (mandatory):
    ## Story: {title}
    **As a** {specific role}, **I want** {capability}, **so that** {benefit}
    
    ### Acceptance Criteria
    - Given {context}, When {action}, Then {outcome}
    
    RULES:
    - One story per distinct user capability
    - 3-5 acceptance criteria per story in Given/When/Then
    - Tag data sensitivity: Public/Internal/Confidential/Restricted
    - Include regulatory linkage (cite KB section) if applicable
    - If insufficient context for a field, write INSUFFICIENT_CONTEXT:[what's missing]
    
    GROUNDING (mandatory):
    - Only use information from the provided input and knowledge base
    - Never invent system names, API endpoints, or regulatory references
    - Cite which KB section informed each story
    
    REFLECTION (mandatory):
    After generating all stories, self-review:
    1. Does every story trace to the input feature?
    2. Are all AC specific, measurable, testable?
    3. Are all domain terms from the KB?
    4. Revise any issues before returning.

  input_schema:
    type: object
    required: [feature_description, epic_key, epic_context]
    properties:
      feature_description: {type: string, max_length: 5000}
      epic_key: {type: string, pattern: "^[A-Z]+-\\d+$"}
      epic_context: {type: string}

  output_schema:
    type: array
    min_items: 1
    max_items: 15
    items:
      type: object
      required: [title, user_story, acceptance_criteria, data_sensitivity, citations]
      properties:
        title: {type: string, max_length: 200}
        user_story: {type: string}
        acceptance_criteria:
          type: array
          min_items: 3
          max_items: 5
          items: {type: string}
        data_sensitivity: {type: string, enum: [Public, Internal, Confidential, Restricted]}
        regulatory_linkage: {type: string, nullable: true}
        citations:
          type: array
          items:
            type: object
            properties:
              kb_name: {type: string}
              section: {type: string}
        reasoning:  # CoT — logged for audit, stripped from downstream
          type: object
          properties:
            capability_addressed: {type: string}
            kb_sections_used: {type: array, items: {type: string}}
            sensitivity_rationale: {type: string}

context:
  knowledge_bases:
    - kb-L1-enterprise-security
    - kb-L1-sdlc-templates
    - kb-L2-payments-domain
  guardrails:
    - gr-L1-output-schema-validator
    - gr-L1-pii-detection
    - gr-L1-hallucination-check
    - gr-L2-payments-compliance
    - gr-L2-payments-terminology
  tools:
    - L1-jira-fetch-issue

quality:
  patterns:
    reflection: {enabled: true}
    grounding: {enabled: true, mode: strict, citation_required: true}
    chain_of_thought: {enabled: true, audit_logged: true}
    verification: {enabled: true, verifier: L1-quality-verifier-agent, min_score: 7.0}
  evaluation_rubric: story-quality-rubric-v1
  min_score: 7.0

performance:
  target_latency_seconds: 30
  max_token_budget: 8000
  estimated_cost: "$0.04/invocation"

error_handling:
  on_invalid_input: "Return ToolResult(success=false, error=field-level details)"
  on_model_error: "Retry once with same input; if fails, return error with correlation_id"
  on_quality_gate_fail: "Return output with score; flag for HITL"

versioning:
  instruction_hash: "sha256:def456..."
  input_schema_version: "1.0"
  output_schema_version: "1.2"
  kb_versions:
    kb-L1-enterprise-security: "2.1.0"
    kb-L1-sdlc-templates: "1.0.0"
    kb-L2-payments-domain: "2.1.0"

5. Workflow — End-to-End

Workflow Spec

spec_version: "1.0"
artifact_type: workflow
metadata:
  name: L1-WF-sdlc-initiative-to-pr
  version: "1.0.0"
  layer: L1
  owner: ai-tech-lab
  description: "End-to-end: initiative → epics → stories → design → code → tests → PR"

trigger:
  type: manual  # or jira-label
  input:
    initiative_description: {type: string, required: true}
    jira_project: {type: string, required: true}
    github_repo: {type: string, required: true}

steps:

  # ── PHASE 1: INCEPTION ──
  
  - name: create-epics
    agent: L1-inception-epic-creator-agent
    input:
      initiative: "${input.initiative_description}"
    output: epics
    quality_gate: {rubric: epic-quality, min_score: 7.0, on_fail: hitl-review}
    guardrail_chain: [gr-L1-output-schema-validator, gr-L1-hallucination-check]
    timeout_seconds: 60

  - name: decompose-features
    agent: L1-inception-feature-decomposer-agent
    input:
      epics: "${steps.create-epics.output}"
    output: features
    quality_gate: {rubric: feature-completeness, min_score: 7.0, on_fail: hitl-review}
    guardrail_chain: [gr-L1-output-schema-validator, gr-L1-hallucination-check, gr-L2-payments-terminology]
    timeout_seconds: 90

  - name: generate-stories
    agent: L1-inception-story-generator-agent
    input:
      features: "${steps.decompose-features.output}"
    output: stories
    quality_gate: {rubric: story-quality, min_score: 7.0, on_fail: hitl-review}
    verification: {agent: L1-quality-verifier-agent, min_score: 7.0}
    guardrail_chain: [gr-L1-output-schema-validator, gr-L1-pii-detection, gr-L1-hallucination-check, gr-L2-payments-compliance]
    timeout_seconds: 120

  - name: generate-tasks
    agent: L1-inception-task-generator-agent
    input:
      stories: "${steps.generate-stories.output}"
    output: tasks
    quality_gate: {rubric: task-completeness, min_score: 6.0, on_fail: hitl-review}
    timeout_seconds: 90

  - name: write-inception-to-jira
    agent: L1-jira-orchestrator-agent
    tools: [L1-jira-create-issue]
    input:
      project: "${input.jira_project}"
      epics: "${steps.create-epics.output}"
      stories: "${steps.generate-stories.output}"
      tasks: "${steps.generate-tasks.output}"
      labels: ["aava-generated"]
    output: jira_issues
    idempotency: check-before-create
    on_error: retry(max=2)

  # ── PHASE 2: DESIGN ──

  - name: generate-ux-wireframes
    agent: L1-design-ux-wireframe-agent
    input:
      stories: "${steps.generate-stories.output}"
    output: ux_design
    quality_gate: {rubric: ux-completeness, min_score: 7.0, on_fail: hitl-review}
    timeout_seconds: 120

  - name: generate-hld
    agent: L1-design-hld-agent
    input:
      stories: "${steps.generate-stories.output}"
      features: "${steps.decompose-features.output}"
    output: hld
    quality_gate: {rubric: hld-quality, min_score: 7.0, on_fail: hitl-review}
    verification: {agent: L1-quality-verifier-agent, min_score: 7.0}
    timeout_seconds: 120

  - name: generate-api-spec
    agent: L1-design-api-spec-agent
    input:
      stories: "${steps.generate-stories.output}"
      hld: "${steps.generate-hld.output}"
    output: api_spec  # OpenAPI 3.0 YAML
    guardrail_chain: [gr-L1-output-schema-validator]  # validates OpenAPI schema
    timeout_seconds: 90

  - name: generate-lld
    agent: L1-design-lld-agent
    input:
      hld: "${steps.generate-hld.output}"
      api_spec: "${steps.generate-api-spec.output}"
    output: lld
    quality_gate: {rubric: lld-quality, min_score: 7.0, on_fail: hitl-review}
    timeout_seconds: 120

  - name: upload-designs-to-github
    agent: L1-github-orchestrator-agent
    tools: [L1-github-upload-file]
    input:
      repo: "${input.github_repo}"
      files:
        - {path: "designs/ux-wireframes.md", content: "${steps.generate-ux-wireframes.output}"}
        - {path: "designs/hld.md", content: "${steps.generate-hld.output}"}
        - {path: "designs/lld.md", content: "${steps.generate-lld.output}"}
        - {path: "designs/openapi.yaml", content: "${steps.generate-api-spec.output}"}
      branch: "aava/design-${input.jira_project}"
      message: "feat: add designs [aava-generated]"
    output: design_commit

  # ── PHASE 3: CONSTRUCTION ──

  - name: generate-code
    agent: L1-construction-code-generator-agent
    input:
      lld: "${steps.generate-lld.output}"
      api_spec: "${steps.generate-api-spec.output}"
      stories: "${steps.generate-stories.output}"
    output: code_files  # array of {path, content}
    quality_gate: {rubric: code-quality, min_score: 7.0, on_fail: hitl-review}
    verification: {agent: L1-quality-verifier-agent, min_score: 7.0}
    timeout_seconds: 180

  - name: upload-code-to-github
    agent: L1-github-orchestrator-agent
    tools: [L1-github-upload-file]
    input:
      repo: "${input.github_repo}"
      files: "${steps.generate-code.output}"
      branch: "aava/impl-${input.jira_project}"
      message: "feat: implement transfer service [aava-generated]"
    output: code_commit

  # ── PHASE 4: TESTING ──

  - name: generate-test-scenarios
    agent: L1-testing-scenario-writer-agent
    input:
      stories: "${steps.generate-stories.output}"
      api_spec: "${steps.generate-api-spec.output}"
    output: test_scenarios
    quality_gate: {rubric: test-coverage, min_score: 7.0, on_fail: hitl-review}
    timeout_seconds: 120

  - name: generate-test-cases
    agent: L1-testing-case-writer-agent
    input:
      scenarios: "${steps.generate-test-scenarios.output}"
    output: test_cases  # Cucumber format
    guardrail_chain: [gr-L1-output-schema-validator]
    timeout_seconds: 90

  - name: push-tests-to-xray
    agent: L1-jira-orchestrator-agent
    tools: [L1-xray-create-test]
    input:
      test_cases: "${steps.generate-test-cases.output}"
      linked_stories: "${steps.write-inception-to-jira.output}"
    output: xray_tests

  # ── PHASE 5: PR CREATION ──

  - name: create-pull-request
    agent: L1-github-orchestrator-agent
    tools: [L1-github-create-pr]
    input:
      repo: "${input.github_repo}"
      head: "aava/impl-${input.jira_project}"
      base: "main"
      title: "feat: domestic fund transfer [${input.jira_project}] [aava-generated]"
      body: |
        ## Summary
        Implements domestic fund transfer capability.
        
        ## Jira Issues
        ${steps.write-inception-to-jira.output.issue_keys}
        
        ## Design Docs
        - designs/hld.md
        - designs/lld.md
        - designs/openapi.yaml
        
        ## Test Coverage
        ${steps.push-tests-to-xray.output.test_count} test cases in XRay
        
        Generated by AAVA workflow L1-WF-sdlc-initiative-to-pr v1.0.0
    output: pull_request

orchestration:
  execution_mode: sequential
  max_total_timeout_seconds: 1800  # 30 minutes
  correlation_id: auto-generated
  audit_trail: every-step
  
  events_emitted:
    - workflow.started
    - step.{name}.started
    - step.{name}.completed
    - step.{name}.quality_gate.{pass|fail}
    - step.{name}.verification.{pass|fail}
    - step.{name}.guardrail.{pass|violated}
    - workflow.completed
    - workflow.failed

hitl:
  type: jira-subtask
  assignee: workflow-triggerer
  sla_hours: 24

8. What This Architecture Achieves

ConcernHow It's Addressed
**Consistency**Every agent has a spec with output schema. Guardrails enforce schema compliance.
**No hallucination**Grounding enforcement + citation requirement + hallucination guardrail + verification agent
**Traceability**Every output item cites its KB source. Correlation ID links all steps. Version manifest records every input dimension.
**Quality**Quality gates (rubric ≥ 7.0) between every step. Verification agent provides independent review.
**Security**PII guardrail on all agents. Secrets via SDK. Data classification tagged on every story.
**Auditability**CoT reasoning logged. Every step emits events. Full version manifest per execution.
**Resilience**Retry on tool failures. HITL on quality gate failures. Timeout per step and workflow.
**Cost control**Token budget per agent. Temperature 0.2 for structured output. Only necessary KBs attached.
**Regression safety**Version manifest captures every input dimension. Any change triggers targeted regression.
**Extensibility**L2 domain agents extend L1 via instructions_append. L3 squad agents extend L2. No duplication.
